CPE Operations

CPE has no image and no process of its own. The Access Area's binary, access-server, serves it beside DPE, and the image is the one DPE Operations describes. This page holds what is specific to CPE.

What is served

  • Where: every path under /cpe (CPE_BASE). A project is at /cpe/<project id>/; today there is one, Incunabula, at /cpe/incunabula/. /cpe and /cpe/ are CPE's overview: the projects it serves, each with a link to its start page. Any other path that names no project is CPE's own not-found page.
  • From what: the project folders in CPE_PROJECTS_DIR (configuration, narrative, assets) and sync's data in SYNC_DATA_DIR. Both are in the image. Each project's store is built in memory from that data at every start; nothing is written to disk, and a restart leaves nothing behind.
  • Static files: CPE's stylesheets, scripts and logos are compiled into the binary and served at /cpe/<project id>/_static/…, and at /cpe/_static/… for the overview and CPE's not-found page; a project's own files at /cpe/<project id>/_assets/….

Configuration

The four variables (CPE_BASE, CPE_PROJECTS_DIR, CPE_PUBLIC_ORIGIN, SYNC_DATA_DIR) are in the environment table of DPE Operations. The image sets all but CPE_PUBLIC_ORIGIN. The three CPE_* values can also come from a cpe.toml in the working directory; the environment wins.

Start-up, and what CPE answers when something is missing

The port is bound first, and CPE's projects are loaded afterwards, in the background. Until they are, every path under /cpe answers 503 with Retry-After: 30 and Cache-Control: no-store. DPE and /healthz answer throughout. Nothing of CPE's stops the binary or delays its start.

/healthz says nothing about CPE. Whether Incunabula is served is read from the log line CPE's projects are loaded (served, unavailable) or from the status of /cpe/incunabula/.

A CPE request is traced by the binary's layers, under DPE's telemetry identity, with a span named by CPE's route (GET /cpe/incunabula/books/{id}).

Measurements

Measured on 2026-10-12. Two set-ups, both with the image's environment and the committed data (Incunabula: 4,198 resources, 20.3 MB in SYNC_DATA_DIR):

  • The image, built from a staged context as CI builds it, but for linux/arm64 (CI builds linux/amd64): a static musl binary, run with docker run --cpus=1 --memory=512m, the limits of a PR preview, under Docker Desktop on an Apple M5 Max.
  • The host: the release binary run on macOS on the same machine, from a directory laid out as the image.

/healthz answered 200 before the log line CPE's projects are loaded in every run, and the first request to /cpe/incunabula/ answered 503. The memory figures are of the whole process, DPE included: the peak is reached while the project is loaded, and the snapshot, the built rows and the SQL text are freed afterwards. The 61,064 requests are a crawl of every URL Incunabula's pages link to, 48 at a time against the image and 8 against the host; after it Docker reported the container healthy, with no restart and no out-of-memory kill.

A PR preview on Cloud Run is deployed with --no-cpu-throttling. With throttling, an instance gets CPU only while it handles a request, and /cpe/incunabula/ answered 503 after a cold start until the sixth request. The load time on Cloud Run without throttling is not measured.

The image's data grew by 195,708 bytes (23 files, cpe/projects): the staged directory without the binary was 69,819,957 bytes before and is 70,015,665 bytes with it. sync/data (20,281,022 bytes) was already staged.

Response times: the baseline for store reads on the request path

A page's store reads run on the async worker threads the binary shares with DPE, and one project's requests wait on one lock (ARCH-MAP.md, areas/access/cpe). These figures are what a change to that is compared with. Times are to the last byte.

Every URL Incunabula's pages link to (61,064) was asked once by one client, on the host: median 1.0 ms, 95th percentile 1.9 ms, 99th 2.1 ms, slowest 9.5 ms. The slowest pages of that pass and five ordinary ones (18 pages) were then asked thirty times each by one client, and by eight clients at once, each its own process, 25 rounds over the list:

Tests that start the binary

DPE's Playwright suites (end-to-end and accessibility) start access-server without CPE_BASE, so CPE is not mounted in them. just run and just dev set CPE_BASE=/cpe.
