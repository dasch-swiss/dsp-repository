## Closeout

- root_cause: Four independent gaps found by the 2026-10-28 stage test. DEV-7711 was not format-related: on a posted re-render (Add, Remove, a refusal, the autosave) the spatial-coverage reference row read `{row}.url` where the other row shapes read `{row}.ref.url`, so the typed value rendered empty and the next write stored the blank; and no format rule existed, so nothing could show an inline error. DEV-7685: link and DOI members had no value kind, so any string was accepted and a broken `href` reached DPE. DEV-7695: the editor knew only published projects; an assigned unpublished shortcode had nothing to fill in, and a seeded `id`/`pid` would have made `classify_record` read a new project as `RemovedUpstream`. DEV-7677: identity had no way to ask whether a shortcode is known, since `deposit-server` may not depend on `editor-core` and identity starts before the editor.
- investigation: Phase 1 began with a Playwright reproduction per row shape in both passes, capturing the POST body; it showed the value was posted and then emptied by the re-render, not dropped in `apply_and_store`, which ruled out the plan's stage-only and morph hypotheses (1.1). Findings are computed in `view()` from the stored draft rather than carried by the write path, and matched to posted rows by value, after positional mapping was set aside as a copy of the appliers' drop rules. The corpus walk set the rule's shape: 122 committed `http://` values ruled out a strict `https://` rule, and the `url` crate alone passed `https://Basel` and `https://dasch..swiss`, so `Link` adds a dotted-host and spelled-out-scheme check (2.1, tightened after review). The security review found `javascript:` reaching DPE through the data management plan, which gained its own `LinkOrNotAccessible` kind. In phase 3 a released created project would never go Online once RDU adds its licence in git, which led to the owner's git-owned rule for display-only members. Phase 4 used the existing `OpenWork` port (`unknown_projects`) instead of the sync `bool` the issue sketched, given the composition-root rule and start order.
- solution: `editor_core::form::format` (value kinds `Link`, `DoiOrLink`, `LinkOrNotAccessible`, declared with `Field::formatted`), findings rendered inline through the tiles' `error` builder, a submit gate and RDU review/approve re-checks, messages in `widgets::format_message`, and the entity proposal gate (DEV-7711, DEV-7685; DPE links a bare DOI through `https://doi.org/`). RDU project creation: the `created_projects` registration with `CreatedProjectRepository`, `/projects/new` and `/projects/{shortcode}/remove`, a seeded draft (`shortcode`, `id`, `pid`, name, `howToCite`, `legalInfo`), `classify_record` taking the created set, a startup sweep ending the registration once published, `GIT_OWNED` display-only members, a corpus test refusing an empty `legalInfo`, and PRD US-8 in dasch-specs (DEV-7695). `OpenWork::unknown_projects`, implemented by `LiveOpenWork` and wired by `deposit-server`, drives the per-account warning on `/depositors`; Name and Email gained hints (DEV-7677). ADR-0003 and ADR-0004 revised.
- prevention: Tests: `row-controls.spec.ts` per row shape in both passes; `format_corpus.rs` (every committed project and entity zero findings, 0110 named); `published_licence.rs` (no empty `legalInfo`); handler parity tests for Save, Add, Submit and the plain-POST path; `depositor_vocabulary.rs` extended; the cross-capability test for the unknown-shortcode warning. Pattern: compute render-time findings from stored state in `view()`, never on the write path; share one helper for every reference row's member names. Anti-patterns: a field-specific member path in a row widget; a validation rule chosen without walking the committed corpus first. Open, not fixed here: the approve gate's read-to-transaction window (needs a version check in `ReviewRoundRepository::approve`), the 320px repeatable-row overflow in mosaic, and DEV-7744 (DPE `href` scheme check, email rule).
