## Chunk queue

Paths under `E/` = `areas/deposit/editor/`, `M/` = `modules/mosaic/`. Commit plan: plan commit first, then one commit per issue; within a phase the first code commit carries the issue's subject and every later commit of that phase is `fixup!` of it, folded in phase 5.

Phase 1 design (session decisions from grounding): Mosaic tiles have no Datastar dependency, so the combobox tile takes the caller's `shared_datastar::get(..)` expression as an opaque string and the playground shows it statically (no Datastar script there). Results are a `ul role=listbox` of `button type=submit role=option` choose buttons (roving focus; Enter submits natively through `#section-form`), fed by a `GET …/agents?for=<unique>&q=` fragment answering `text/html` morphed by id, always 200. Modes: a chosen agent renders as a card; an empty slot, or one whose Change was pressed (`change-agent:<unique>`, kept while `<unique>.q` is posted), renders the combobox; contributors and contact point get one append search (`<field>.new`, choose intent `add-agent:<field>:<id>` appends a row). Role chips are display-only over the checkbox set in a "Choose roles" `<details>` (open while no role); chip Remove is `remove-role:<prefix>:<index>`. Organisation detail line uses `alternativeName` (no acronym field exists on `Organization`). CSP is `frame-ancestors` only, so the inline `onkeydown` (DPE precedent) is allowed.

Phase 2 design (session decisions): the enhanced path navigates with a `200` `text/javascript` body `window.location.assign(<json url>)` (`handlers::navigate`; Datastar 1.0.2 runs it as a script once per response), not a separate form outside the section form: the section POST stores the posted body before proposing (`act` → `apply_and_store`), which a separate form would skip, losing unsaved no-JS edits. Plain path 303. (First built as a `data-init` element in the region; the review found an identical morph does not re-fire after Back.) Return path: `entity::origin::Origin` (`?section=&field=`, hidden inputs `section`/`field`), validated against `registry::sections_for(audience)` and that section's agent-picker fields; anchor `{field}-card-{entity}` on the first card per agent per field. Propose intent `propose-changes:{field}:{entity}`; a live proposal for the entity is opened instead of refused. Discard → top of the section with `?discarded_proposal=` (section `show`, confirmed while withdrawn); New → `withdraw_rewriting_draft` (withdraw + `drop_agent` on the draft in one store transaction, skipped while a submission is pending), named in the discard confirmation. New-proposal starts keep the section notice (link carries `?section=`).

Phase 3 design (session decisions): `disciplines` rows get a third variant `snsf` ("From the SNSF list", a select of the 141 codes posting `disciplines.<row>.snsf`) beside `reference` (renamed "From the UNESCO nomenclature", link + label while the list is deferred, Source option shown as "UNESCO nomenclature", value `Skos`) and `text`; `temporalCoverage` keeps its two. A stored text row is SNSF when its first coded value (any language) names a listed code (`disciplines::snsf_row`); group codes (`10400`) render as own wording. Save: an unchanged code keeps the stored row verbatim (so `de`/`fr` values and every committed file survive), a new pick stores `{"en": "<code> <name>"}`, an SNSF row with no listed code is not stored (changed in 3.4; first built to fall back to the posted text). A pasted UNESCO link is stored as typed (see Deviations). Both untouched-form simulators (core test, web `untouched_body`) post the new branch, so the whole-corpus round trip covers it.

Phase 4 design (session decisions, owner-confirmed 2026-11-04): pickers are the phase 1 combobox over bundled lists, fed by one non-writing `GET …/sections/{section}/vocabulary?for=<picker>&q=` fragment beside `/agents`; the no-JS Search button posts `intent=find-entry`, handled like `find-agent` (store, re-render with the body kept). An option posts `intent=pick:{prefix}:{value}` (a URL for places and periods, an SNSF code for disciplines; the prefix never holds a colon, so the value may); the pick is rewritten, before the appliers, into the pairs the controls post (`kind=snsf` + `snsf=<code>`, or `kind=reference` + `ref.type/url/label`), so `apply_text_or_reference_rows`, `apply_reference_rows` and `stored_kind` stay the single path and the untouched-form simulators are unchanged. Disciplines: the SNSF select is replaced by a hidden `{prefix}.snsf`, the chosen discipline as text and a combobox over `disciplines::search` grouped by domain (the select's 141 options per row are gone); the UNESCO branch keeps link + label (probe still down). Spatial and temporal coverage: a combobox above the three reference controls; a pick fills them, a place or period outside the list is typed in them as before. Periods: the owner chose the full ChronOntology list (every mirrored period with a name and a resolvable timespan) over the 51 in use or a live lookup (PRD line 35: no new external vendor; submit resolves against the local mirror). The committed slim mirror holds no names, so `scripts/build-coverage-vocabularies.py` reads a full mirror from `fetch-chronontology-periods.py` (`.claude/tmp`, gitignored; chronontology.dainst.org cuts pages above ~64 KB, so 20-record pages with retries).

## Closeout

- root_cause: the v1 plan carried the prototype's flow but not its pickers, so recognised values (a contributor, a discipline, a place, a period) could only be recorded by typing or pasting a link, and the SNSF list DaSCH uses most had no representation in the editor at all.
- investigation: the section form's POST stores before it branches, so the type-ahead needed its own non-writing `GET` fragment; Datastar processes only a `200`, so the proposal flow navigates with a `text/javascript` body rather than a followed `303`; a place url can carry two labels, so a pick names `{url} {label}`; the committed ChronOntology mirror holds no names, so periods come from a live-fetched mirror, limited to what DPE's slim file resolves; same-named periods outnumber the result cap, so the detail line is searched too. UNESCO's server was unreachable all day, so its list is a follow-up.
- solution: a Mosaic combobox tile (roving focus, grouped results, no-JS Search + choose buttons) and one rewrite of picker intents into the row's own posted pairs, used by contributor and contact-point cards (DEV-7702), the card's proposal flow with a validated return path (DEV-7686), an SNSF branch for disciplines (DEV-7710), and searches over bundled SNSF, place and period lists built by checked-in scripts (DEV-7698).
- follow-up: [DEV-7750](https://linear.app/dasch/issue/DEV-7750) (bundle the verified UNESCO nomenclature and offer it beside SNSF), added to the post-pre-prod issues update.
- prevention: drift tests tie each bundled list to the corpus and to submit's resolution; handler tests pin the fragments' `200`/`404` and that a pick stores the committed shape; a registry test pins each list to its row shape; E2E covers every picker in both passes, including keyboard; ARCH-MAP records the two redirect mechanisms and the derived data's writers.
